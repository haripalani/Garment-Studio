# Stage 8 Report: Cloud App and Staging

- **Status:** awaiting approval
- **Date:** 2026-10-31
- **Decisions:** ADR-0021 (amends ADR-0009, 0011, 0016)

## What was built

### Accounts in the editor
- **Sign-in dialog** connected to the API: log in (remember me), sign up, email link, forgot password.
  - Server answers become plain sentences (wrong password, account locked, too many attempts, email taken, service unreachable).
  - Invalid input is caught before anything is sent.
- **Email-link pages** `/auth/verify`, `/auth/magic` and `/auth/reset` complete the flow and return to the editor.
- **Header:**
  - An account menu (email, plan, resend confirmation, log out).
  - A status line: *Saving… · Saved to cloud · Saving to cloud… · Offline: saved on this device · Confirm your email to save to the cloud · Plan limit reached · Edited elsewhere: your version was kept as a copy*.
  - **Save to the cloud now**, which asks you to log in when signed out.
- **Sessions:**
  - The access token is kept in memory and the refresh cookie restores the session on reload.
  - Refreshes are serialised across tabs (Web Locks).
  - A temporary failure means "offline, try again", never "signed out".

### Local-first sync (ADR-0009 / 0021)
- **Local library:** every design is saved on the device first, together with its sync state. The old single working copy is migrated once, and ids are valid in the cloud from the start.
- **Push:** after a local save, missing images upload straight to storage (presigned, deduplicated), then a revision is pushed with optimistic concurrency and a content hash.
- **Pull:** on focus, on reconnect, every minute, and **live** when another device saves (WebSocket `project.updated`).
- **Three-way merge** per layer and per look section. Changes from another device arrive in the editor as **one undoable step**.
- **Conflicts:** when both sides changed the same thing, the cloud version stays and this device's version becomes **"‹name› (conflicted copy)"**, linked to the original. Nothing is dropped.
- **Edge cases:**
  - gestures are pushed when they end
  - a pending save is never lost when switching designs
  - untouched new designs don't clutter the list
  - deleting waits for a running upload
- **Project browser:** designs on this device and in your account in one list, with thumbnails, badges (*Open now*, *In your account*, *This device only*, *Conflicted copy*) and edited time. You can open, rename, duplicate, move to trash and restore.
- **After signing in:** an offer to save designs made while signed out to the account.

### Plans in the editor
- **Cloud render** from the render dialog: the design is saved first, then the job is queued with live progress (WebSocket, with polling as fallback). The result is shown, and you can save it as PNG or WebP or cancel the job.
- **Export quota:** exports are counted against the plan *before* the file is made (a used-up quota stops the export). Offline exports are reported when the connection is back.
- **Free-plan watermark:** added in the editor for local renders, snapshots and video, and **by the render worker** for cloud renders, so the server enforces it.

### API changes for the cloud app
- **New:**
  - `GET /assets?sha256=…`: another device fetches a design's images by content hash.
  - `conflictOf` on project creation.
  - `COOKIE_DOMAIN`, for `app.` and `api.` sibling subdomains.
  - `S3_PUBLIC_ENDPOINT`, which presigns browser URLs for the address browsers use.
  - A bucket CORS policy set at start-up, so browsers can upload with an `ETag`.
  - A configurable sign-in limit (`RATE_AUTH_PER_MIN`, default 10).
  - Session refresh moved off the strict sign-in limit.
- **Fixed:** browser preflight refused PUT, PATCH and DELETE (see the defects table).

### Staging
- **Images:**
  - `apps/api/Dockerfile`: API, migrations and seed.
  - `apps/api/Dockerfile.worker`: GPU render worker with Playwright Chromium and the built editor.
  - `apps/editor/Dockerfile`: static editor on Caddy.
- **Staging replica** (`infra/staging`):
  - The production images behind **HTTPS on one origin** (Caddy, local certificates).
  - The API in **production mode**, with its config checks on: antivirus required, Secure cookies.
  - Path-routed `/v1` (including the WebSocket) and a separate storage host for presigned URLs.
  - A release step that runs migrations and the seed.
  - Secrets generated by `make-env.mjs`, git-ignored.
- **Staging smoke test** (`playwright.staging.config.ts`), against the replica or real staging: sign up, confirm by email, upload an image through the proxy (scanned by ClamAV), save to the cloud, reload with Secure cookies.
- **CI** (`.github/workflows/ci.yml`):
  - typecheck, unit tests, builds and OpenAPI lint
  - API integration tests with the Docker services
  - Chromium E2E against the real API
  - GPU render tests skipped (hosted runners have no GPU)
- **Real staging:** `infra/fly/api.staging.toml` and `infra/DEPLOY.md` (accounts, secrets, deploy, verify).

## Defects found and fixed during Stage 8

| # | Finding | How found | Fix |
|---|---|---|---|
| 1 | **Browser preflight refused PUT, PATCH and DELETE**: thumbnails, renaming and trashing failed in browsers. The API tests couldn't see it (Node's fetch ignores CORS) | Browser console | Explicit CORS methods; API preflight test |
| 2 | **Session refresh hit the 10/min sign-in limit**: a shared IP or several tabs looked signed out | E2E (parallel) | Refresh in the write class; configurable sign-in limit; a temporary failure shows as "offline" |
| 3 | **Edits made during a gesture weren't pushed when it ended** (the other device saw the placeholder text) | WebKit E2E timing | Push and pull wait for the gesture to end |
| 4 | **Switching designs during the 0.8 s autosave delay lost the previous design's last edits** | Code review while building "New design" | The previous design is saved straight away when the open design changes |
| 5 | The legacy working copy was **migrated twice** (React's dev double effects, or two tabs) | Project browser in the browser | Deterministic id and a single shared migration |
| 6 | Trashing a just-duplicated design raced its first upload, so it came back | E2E | Delete waits for the design's pending sync |
| 7 | Opening the project browser saved the untouched empty design as a project, which then shadowed the real one | E2E (second device) | Untouched new designs aren't saved |
| 8 | Restore, then switching view: a slow earlier load overwrote the list | E2E | Only the newest load updates the list |
| 9 | WebKit dropped Secure cookies on `http://localhost`, so the session was lost on navigation | WebKit E2E | Local http dev uses non-Secure cookies (production refuses that); HTTPS replica verified with Secure cookies |
| 10 | No thumbnails when the 3D view is closed | Database check | 2D front-piece thumbnail fallback |
| 11 | A signed-in user with a new, empty design was told "Saved on this device" | E2E | An untouched design counts as saved |

## Not done / limitations (transparent)
- **Real staging is not deployed.** It needs your accounts and billing: a domain, Cloudflare (Pages, R2), Fly.io, Neon, Upstash, Postmark, a GPU host and GitHub secrets. `infra/DEPLOY.md` lists each step. The replica proves the images and routing, not those providers.
- **CI has never run.** The workflow needs a push to GitHub; expect a fix-up round on its first run.
- **Cloud renders on staging:** the worker image and GPU flags for Linux NVIDIA are untested, because this machine has no GPU path into Docker. The worker itself is tested natively on Windows.
- **Email deliverability** (SPF, DKIM) is untested; all mail went to Mailpit.
- **Signed-out use** is unlimited and local; whether exports should require an account is a product decision (D3).
- **Free-plan watermark** on local renders is applied in the browser, so it can be bypassed; cloud renders are watermarked by the server.
- **Shared computers:** another account's local designs stay on the device, hidden while you're signed in. There's no "remove from this device" yet.
- **No real-time co-editing:** simultaneous edits to the same layer produce a conflicted copy.
- **Local http development needs `COOKIE_SECURE=false`** (WebKit); staging and production use HTTPS and Secure cookies.
- **Saving in the last 0.8 s before closing the tab** relies on the browser finishing the IndexedDB write during `pagehide`, which is best effort.
- **This browser's own local data** has a duplicate of the old working design, from issue #5 before the fix. It's harmless.
- **E2E on this laptop is CPU-bound:** headless browsers draw 3D in software. The full suite takes ~25 min and sits close to its time limits; heavy tests are isolated and run on 2 workers. A clean full run including the chained heavy phase was not achieved in Stage 8 (see Verification).
- Nothing from Stages 7–8 is committed yet.
